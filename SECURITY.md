# Security policy

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
or pull request.

When private vulnerability reporting is enabled for the public repository, use
that mechanism. Until then, contact a project maintainer through an existing
private channel and include a minimal reproduction, affected revision, impact,
and any suggested mitigation. Do not include credentials, private keys, access
tokens, or sensitive customer data.

## Scope and expectations

Boxwarden is early-stage software and is not ready for general use. Reports
about VM containment, guest-to-host integration, credential handling,
networking, lifecycle reconciliation, profile persistence, and supply-chain
qualification are particularly useful.

The project will make a good-faith effort to acknowledge reports, assess
impact, and coordinate a fix. No response-time or compatibility guarantee is
made at this stage.

## Supported versions

No release line is currently supported. The default reporting target is the
latest `main` revision in the public repository once publication occurs.
