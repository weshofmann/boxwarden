# Executable diagnostic interface addendum

This adds implementation interfaces to the merged two-gap design. It does not
alter historical verdicts, authorize installation or a live window, or qualify
N1. The source baseline is merged PR17 `bbcfaac3f3e21b7094b2db4476c54115eb43722e`.
The completed package ledger must distinguish proposed interfaces from verified
implemented coverage.

## Clipboard metadata boundary

The generic golden bootstrap helper and canonical production adapter remain
byte-identical. Adapter-only staging cannot observe Bootstrapper internal
branches. Each future fresh clone therefore receives a separately named,
digest-admitted `/usr/local/libexec/boxwarden-n1-clipboard-diagnostic` trial
helper, the overlay, and the exact production sibling. Ordinary READY bootstrap
continues to use the generic helper. The same trial files are used on stock and
candidate for the diagnostic comparison; their timing may perturb the operation.

Each invocation gets a fresh operation UUID bound to domain, session, backend,
generation, direction and the original expiry. The private diagnostic request
wraps the unchanged production request/frame. The trial helper verifies matching
identities and expiry and sends bounded metadata to the overlay on fixed fd3,
with original direction/deadline argv and closed environment. There is no
caller-selected path/fd, ambient override, text metadata, or extended deadline.
Root-owned fixed files bind bootstrap stages and adapter slots to that operation.
Collection does not construct GTK or retrieve clipboard text.

The clipboard capability uses the independent `n1clipboarddiagnostic` build
constraint. The stock comparison CLI enables this capability with stock Softnet;
the candidate combines it with `n1diagnostic` network admission. Default and
canonical `n1candidate` builds retain ordinary clipboard behavior. There is no
runtime network identity selection. Host diagnostic tags never replace the
canonical generic helper artifact.

The intended guestproto seam uses two build-constrained implementations of the
same `Bootstrapper.Clipboard` method. The default body remains exact, with a
relative `//line clipboard.go:378` mapping after its minimal source move; this
preserves the generic artifact's historical code/line tables. A bounded copied-
source experiment rebuilt the locked helper byte-for-byte twice and compared
full method disassembly. The diagnostic implementation records actual branches;
shared codecs, Bootstrapper layout/constructor and generic command stay intact.
The intentional small branch duplication requires semantic equivalence checks.
The unchanged canonical artifact test remains authoritative after integration;
the experiment does not certify instrumentation that has not been implemented.

Separate diagnostic actions on the existing private supervisor socket carry
clipboard invocation and receipt collection. Ordinary action schemas stay exact.
The host recorder has at most 32 typed stage records and 16 KiB per operation;
CLI-local stages are a separately bounded fragment, explicitly merged and marked
incomplete if absent. Guest and host monotonic offsets have separate origins.
Fixed enum codes classify existing branches without changing short-circuit order,
write-unknown handling, transfer outcomes, admission or retry behavior. Diagnostic
failure before transfer refuses that diagnostic invocation. Failure after a write
cannot undo it or fabricate failure-before-write: preserve the actual transfer
outcome and mark its receipt incomplete/unknown as appropriate.

The overlay metadata header has exactly version, operation_id, direction, domain,
session_id, backend_kind, backend_object, generation and expires_at. Original
RFC3339Nano expiry maps exactly to the adapter UnixNano argv; it never extends
the deadline. A complete collector receipt covers a finite observed progression
prefix. A live owner requires parent operation completion, original ack observed
before retain_begin, and a stable exact PID/birth/UID/native-owner checkpoint.
It does not require retain_return while the owner is still serving. Missing,
partial, concurrent, malformed or saturated slots and collection/finalization
loss prevent completeness; future retention remains unproved. Task 2 implements
this Python interface with a clean scoped repair review; the actual outer Go
helper and combined integration remain pending as recorded in the ledger.

The Task 2 post-close witness uses fixed fd4, an output-only nonblocking
unnamed pipe supplied by the trial helper. The adapter parent emits one strict
record only after its actual trace descriptor closes and the recording clock
still passes. Its retained owner child closes its inherited fd4 before claim so
it cannot hold the metadata transport open. The record has exactly version 1,
header_digest, direction and elapsed_ms (integer 0–59999), canonical compact
sorted-key ASCII JSON plus one newline, at most 512 bytes. It witnesses parent
trace closure; it does not claim the live owner's future descriptor or retention
lifetime has ended. The original fd3 header stays unchanged.

The root trial helper must independently bound the record through EOF and actual
reader close, compare the exact admitted binding, and publish only the fixed
root-owned direction.closure file after its pending file closes successfully.
The collector requires that proof, ordered parent completion and exact owner
lane progression. It rejects duplicates, conflicting outcomes, misattributed
lanes or native metadata preceding the actual owner checkpoint. Genuine parent
and owner concurrency remains valid. Task 2 implements and independently reviews
the Python corrective interfaces. The actual Go producer remains a separate
unimplemented integration gate, rather than an implicit synthetic certification.

## Private Softnet watch boundary

The diagnostic build creates an unnamed AF_UNIX SOCK_STREAM socketpair owned by
the generation supervisor. Its child endpoint is inherited as fd1 by Tart and
Softnet; Tart fd0/fd2 remain /dev/null, and Softnet replaces only fd0 with its NIC
transport. The ordinary launcher stays unchanged. Pinned Tart Softnet.swift is
SHA256 `18325ef8b6b4098a01aa13e8ed331cd1d1dd2e1fa0fe21570109ff1661db9b64`
at upstream commit `8aa377b71ebfd90b2df9803d3e20033f58d6800c`.
A deterministic Foundation child fixture must verify full-duplex inheritance.
Any incidental Tart stdout invalidates metadata; never retain it or resynchronize.

A compile-time diagnostic selector contains only exact generation and launch
nonce, as one Tart block argument. It selects the distinct admitted executable,
not a policy exception. There is no path, address, duration or fd override in the
selector. Stock, canonical N1 and diagnostic manifests/executables are distinct.

After privilege drop, the child uses strict bounded frames: HELLO, one ARM after
both guests have current READY/pins/backend-address/MAC observations, ARMED, and
one SUMMARY at the finite local deadline. Existing private supervisor actions
arm and retrieve that exact operation; there is no rearm or generic command.
Frames are length-prefixed, exact-field decoded, <=4096 bytes each and <=16 KiB
outgoing total. Generation/nonce/pair/interval disagreement, unexpected bytes,
EOF, timeout, overflow, loss or absent summary invalidates completeness.

Candidate address admission rechecks the actual current live Policy DHCP lease.
Peer address/MAC provenance is the exact current backend observation plus
same-generation pinned SSH positives. It is not labeled trusted DHCP-server
lease evidence. Guest route/neighbor reports remain cooperative observations.
Lease changes/expiry or either generation change invalidate the watch. Processing
services control/deadline at bounded dispatch boundaries even under busy drains;
metadata backpressure cannot block forwarding or trigger policy changes.

## Actual forwarding observations

Record exact VM ingress before refresh and the typed reason from the same ARP
policy evaluation that chooses allow/deny. Record actual single Host::write raw
result before result collapse. At host ingress classify same-IP unexpected MAC,
proxy/broadcast/unsupported cases before filters and record actual VM::write
before ENOBUFS becomes Ok. Preserve call order/count, bytes, refresh/fallback,
state and errors. Observer failures only invalidate diagnostics.

The guest tap reports `coverage_scope=identified_pair_headers` and keeps
`zero_count_attribution=false` for unrestricted absence claims. A separate,
fixed `negative_inference` record can identify candidate-only eligibility for
absence of supported, well-formed outgoing matching ARP or TCP22 SYN at this
guest tap. Eligibility requires actual AF_PACKET direction, timely readiness,
a complete loss-free interval, zero matching outgoing counts and no recognized
unsupported or truncated pair headers. It additionally requires driver controls
and qualified guest capture; the observer never certifies those prerequisites.
The driver must validate exact current bindings, before/after route and neighbor
snapshots, the single connect timing/socket phase/errno and bracketing positives.
This can localize failure before observed guest emission; it cannot name the
precise kernel cause or establish global/downstream absence, enqueue or delivery.

A truncated frame without an identifiable IP tuple, or a fragmented ICMP
response without its quoted tuple, cannot be attributed to the pair without
collecting unrelated traffic. Complete means loss-free accounting of
filter-identifiable headers. Recognized matching unsupported headers and
contradictory or missing packet direction invalidate completeness. Live guest
kernel/offload coverage remains unqualified until the future window checks it.

The fixed observation interval begins at readiness emission start. Its readiness
budget is `min(100000, duration_ms*250)` microseconds and closing tolerance is
`min(250000, duration_ms*250)` microseconds. Readiness must leave at least 75% of
the requested interval. Closing tolerance bounds scheduling/receive completion;
it never admits a packet returned at or after the deadline, which is discarded
and invalidates completeness. Early stop, clock regression and excessive
readiness or closing delay also prevent a complete receipt.

Full-length vmnet API success records that API result. It does not prove enqueue,
peer delivery or vmnet internals. Zero counts require ready/stop/drop-complete
coverage. Historical errno113 remains UNQUALIFIED. Fresh guest counters and host
positives are required for the future interval; offline replay proves tests only.

## Verification and authorization

The package requires framing/branch fixtures, descriptor inheritance, child argv
bytes/count, malformed-stream/busy-drain/deadline tests, actual forwarding
comparisons, artifact reproduction, exact admission/cleanup tests and independent
reviews. Static lock and completed attended request bind every obtainable hash.
Only guest/session/generation/address, short-lived credential path/fingerprint,
and process/runtime facts remain future values. One later owner-approved window
permits their independent review without another authorization merely because
IDs were generated; installation and exact cleanup still require owner attendance.
No live operation is authorized by this document.

## Diagnostic quiescence and cleanup boundary

This interface remains proposed until the implementation/review ledger closes it.
The diagnostic digest tree alone adds `launch.lock`: root-owned, dedicated
operator-group readable, mode0440, regular one-link zero-byte and no ACL, under
protected ancestry. Stock and canonical N1 retain their exact two-file trees.
Every diagnostic start takes a nonblocking shared lock before persisted starting
intent; the owner retains it through stop/wait/reap. The diagnostic Softnet
executable independently takes the same shared lock before VM/vmnet effects and
holds it through resource teardown, including error exits. It rejects copied or
relocated execution, absent/replaced lock and conflicting exclusive ownership.
No process creates, repairs or chooses a lock path.

Exact cleanup holds a nonblocking exclusive lock throughout rooted admission,
exhaustive recorded inventory, conservative live-process observation, final
revalidation and descriptor-relative unlink of only `softnet`, `manifest.json`
and `launch.lock`, followed by removal of the exact empty digest directory and
parent fsync. It neither recursively deletes nor signals consumers. Delayed
starts after lock removal must refuse; opened descriptors are revalidated after
acquisition to reject an unlinked or changed inode. Admission reuses strict root,
operator/group, link/ACL/path and paired-tool checks. The lock is ordinary host
quiescence, never runtime ownership or same-UID cryptographic authentication.

Diagnostic lifecycle admission is restricted to the package's exact reviewed
`n1qualification` config/state-root enrollment. Root cleanup independently reads
those exact non-secret config bytes against their digests and expected operator,
not root's ambient configuration. It scans bounded session/runtime namespaces,
including temporary/residue entries, and refuses every retained generation,
foreign or malformed entry, changed mount or uncertain state. Live observation
stays under `internal/qualification`, uses only bounded PID/executable identity,
and refuses active Tart/Softnet/diagnostic controllers or unverifiable census.
It never requests argv/environment or searches homes for unknown roots.
Unrelated running VMs cause refusal and remain untouched. Current-host flock and
libproc behavior and teardown must be checked read-only within the later
approved attended window before installation; deterministic tests do not claim
that host qualification. These are minimum consumer-race/provenance safeguards,
not a generalized production uninstall surface.
